Connect another computer

This token lets this computer access another omp-console computer. Use a dedicated pairing token, keep it on the daemon host, and store only its path in Settings → Advanced → Optional features.

  1. On the other computer, request a one-time pairing code with omp-console-daemon pair --state-dir <state-dir>. Its daemon must be running.
  2. On this computer, submit the code to the other computer's POST /api/pair endpoint. The response sets an omc_device cookie; its value is the access token.
  3. Write that value alone to a regular file on this computer with mode 0600. Enter the file path, URL, ID, and name under Settings → Advanced → Optional features.

Example for a shell on the daemon host. Keep the response header file private and delete it after use:

set -eu
umask 077
printf "Pairing code: "
IFS= read -r -s PAIR_CODE
printf '\n'
case "$PAIR_CODE" in
  *[!A-Z0-9-]*|'') printf 'Invalid pairing code.\n'; exit 1 ;;
esac
HEADERS=$(mktemp)
trap 'rm -f "$HEADERS"; unset PAIR_CODE TOKEN 2>/dev/null || true' EXIT
curl --fail-with-body -sS -D "$HEADERS" -o /dev/null \
  -H 'content-type: application/json' \
  --data "{\"code\":\"$PAIR_CODE\",\"label\":\"omp-console other computer\"}" \
  'https://other-computer.example.ts.net/api/pair'
TOKEN=$(awk 'tolower($1) == "set-cookie:" && $2 ~ /^omc_device=/ { sub(/^omc_device=/, "", $2); sub(/;.*/, "", $2); print $2; exit }' "$HEADERS")
test -n "$TOKEN"
printf '%s\n' "$TOKEN" > "$HOME/.omp-console-peer-token"
chmod 600 "$HOME/.omp-console-peer-token"
unset TOKEN PAIR_CODE
rm -f "$HEADERS"
trap - EXIT

Replace the example hostname and token path. The other computer’s URL must use HTTPS or loopback. Never paste the token into config.json, a URL, issue, or screenshot. Revoke the paired device from the other computer’s daemon under Settings → Devices when the connection is no longer needed.

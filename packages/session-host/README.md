# @omp-console/session-host

Headless worker: one omp `AgentSession` hosted as a collab room, no TUI. One process per session.

On Windows, PowerShell process snapshots and `taskkill /T /F` handle worker descendants; cancelled cleanse checkers and DAP adapters are matched and reaped with their child trees. Shutdown closes the worker-owned auth storage after disposing the session. Git diff and hunk comparisons normalize CRLF on Windows when `core.autocrlf=true`.

```
    bun packages/session-host/src/main.ts --cwd <dir> --relay <ws://host:port> --room <roomId> \
        [--resume <file>] [--fork <file>[:<entryId>]] [--model <selector>]
stdin: first line is a `WorkerLaunchSecrets` JSON object; subsequent lines are worker commands. `abort` interrupts the active turn with the same session abort reason as a writable guest and replies `{t:"aborted", id, aborted:boolean}`; model-change replies echo the command `id`. EOF stops the worker.
The worker environment never contains the room key or write token. `state` lines include the pending dialog question (up to 200 characters) and `ask`/`approval` kind until it resolves.
Host-ticket path routing is blocked until upstream exposes a separate host-only relay URL.

Wire format (stdout status lines, stdin commands): `packages/protocol/src/worker.ts`.

## Request commands (spec items 0.1, 1.9, 2.5, 5.2)

Request-style stdin commands carry an `id`; the reply carries the same `id`. An unknown or malformed command line is logged and ignored (`src/decode.ts`).

Wave-3 control operations add the session-specific controls used by omp console: `pause` engages `agentPauseGate` at safe boundaries without aborting in-flight work and reports `paused`/`pausedAt` on state lines; `queue` splits text with omp's queue splitter and calls `AgentSession.followUp()` in order, attaching images only to the first follow-up; `collab-status` reports the mandatory room and connected participants.

Status lines the worker adds: `ext-ui` (whole state of what extensions publish through `setStatus`, `setWidget` and `notify`, debounced 200 ms, `src/ext-ui.ts`; an `omp-console:<id>` widget holding a valid `DeckPanelDescriptor`, as an object or as JSON in a one-element string array, becomes a panel keyed `<id>`), `usage-sample` (one per finished model request of any agent, `src/usage-samples.ts`; tokens exclude cache reads), `title` (see `refine-title`).

Cleanse status lines include the active run id/status/phase summary; detailed checker results, repair-agent progress and bounded logs are returned by `cleanse-state` for the web board.

Every subagent lifecycle transition on omp's task lifecycle bus (any spawn depth) becomes an `{t:"agent"}` status line (`src/agent-events.ts`): `parentId` from the registry, `profile`, `status`, and on terminal states a `summary` of up to three lines of the agent's result or error, read from the job that ran it.
The state line carries live active/phase/error and the latest transcript preview; the web header and phone session list expose the Live chip. Browser-owned capture and playback are stopped when the page is hidden or the sheet closes.

## Quick replies

The `quick-replies` session operation generates up to ten distinct suggestions for the latest agent answer. Each is limited to 80 characters; parser deduplication and the ten-reply cap also apply to provider output.

## Loop and Vibe modes

`loop-mode` and `vibe-mode` are worker session operations, not slash commands passed to `run-command`; they remain available while a session streams. `/loop [count|duration] [--while|--until <command>] [prompt]` uses omp's argument parser, limit runtime, and shell-condition evaluator. It resubmits the latest user request after each terminal turn and stops on abort, error, condition failure, time limit, iteration limit, explicit disable, or worker shutdown. Loop state is process-local and cleared on shutdown, so sleep or restart cannot resume a stale prompt.

`/vibe [prompt]` activates AgentSession's restricted Vibe tool set (read, optional todo, and Vibe tools), mode context, and the real `VibeSessionRegistry` owner scope. Exit aborts an active parent turn, stops workers in that scope, and restores the saved tool set. Session mode entries are rehydrated on resume; shutdown suspends the scope for omp's registry to reconcile.

The worker state line reports loop progress and condition plus Vibe's active worker ids; the daemon copies these optional fields to `SessionSummary`. The header provides a Loop chip and stop control plus a Vibe toggle. `/loop` and `/vibe` are also available from ⌘K and the composer.
